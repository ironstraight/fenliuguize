Cloudflare 修复指引

先选你要修的入口。按顺序检查，每改一处就复测。

A　远程 LuCI / Zashboard 打不开 B　ClashMi 订阅报 502 / HTML

A　从公网 LuCI 打开 Zashboard

  • 路由器入口　https://h.aspool.ccwu.cc/
  • Zashboard 直达　https://dash.aspool.ccwu.cc/ui/zashboard/

1. 先在家里的网络打开两个面板

LuCI 用 http://192.168.0.1/。Zashboard 用下方完整路径。若局域网也打不开，进 LuCI → 服务 → OpenClash → 运行状态，先确认核心运行、面板端口是 9090。

http://192.168.0.1:9090/ui/zashboard/

2. 先保护公网访问

Cloudflare → Zero Trust → 访问控制 → 应用程序 → 自托管应用 → 编辑 → 公共主机名

可沿用已建的 h 应用，在同一应用里填写两个主机名 h.aspool.ccwu.cc、dash.aspool.ccwu.cc，两行路径都留空。策略用 Allow → Include → Emails，只填获准的邮箱。保存。整站保护会同时覆盖 Zashboard 页面、API 和 WebSocket。

想免收邮件验证码：设置 Passkeys
  1. Cloudflare → Zero Trust → 集成 → 标识提供程序 → 添加标识提供程序 → Passkeys → 保存。已有则跳过。
  2. 回到 访问控制 → 应用程序 → h → 编辑 → 登录方法。关闭「接受所有可用的标识提供程序」，选择 Passkeys 和 One-time PIN，保存。邮件作为备用。
  3. 打开公网 LuCI。在 Access 登录页选「使用 Passkey 登录 → 设置」，按提示完成一次身份验证并保存密钥。以后用 Windows Hello、手机或安全密钥登录；Access 会话到期仍要验证身份。进入 LuCI 后仍用原来的路由器密码。

邮件验证码由 Access 发出。浏览器 Access 会话最长可设为一个月。WAF 是域名的请求过滤规则，管理入口的 Passkeys 与订阅转换器的 WAF 令牌分开。

3. 两条 Tunnel 路由照填

Cloudflare → 网络 → 隧道 → 现有隧道 → 路由 → 编辑路由 / 添加已发布应用程序

  • h.aspool.ccwu.cc → Service URL http://192.168.0.1:80
  • dash.aspool.ccwu.cc → Service URL http://192.168.0.1:9090

两条路由的路径栏都留空。类型和地址分开填时，选 HTTP，地址填 192.168.0.1:端口。站点 → DNS → 记录中检查对应的 Tunnel CNAME 为橙云。容器版连接器的 127.0.0.1 指向容器自身，使用上面的 LAN 地址。

4. 核对按钮并验收

LuCI → 服务 → OpenClash → 插件设置 → 管理页面设置（Dashboard Settings）

公网域名填 dash.aspool.ccwu.cc，映射端口填 443，启用「管理页面公网 SSL 访问」。字段已正确就直接测试。公网浏览器使用 HTTPS，Tunnel 内侧使用上一步的 HTTP。

用手机移动数据验收：打开公网 LuCI → 通过 Access → 登录 LuCI → 服务 → OpenClash → 运行状态 → Zashboard。出现节点或连接即通过。

面板能打开，但看不到节点或连接

先用上方 Zashboard 直达链接。面板的后端地址应为 https://dash.aspool.ccwu.cc，端口 443，使用 OpenClash 现有的管理页面登录密钥。若仍连旧的 LAN 地址，在 Zashboard 添加或切换到公网后端。页面加载但实时连接失败时，核对 Access 已覆盖整个 dash 主机名，并在 Cloudflare → 站点 → 网络核对 WebSockets。

如果公网两个地址都在加载登录页前断开，先换网络试。若只有转换器或面板报 Tunnel 502，检查对应的 Service URL 和该 LAN 端口。恢复时只回退刚改的那条路由或应用字段。

B　订阅 502 / HTML

先重新点一次「一键复制订阅」。清空临时输入后，在 ClashMi 新增配置导入。旧订阅凭据失效可能返回伪装 HTML。若新链接仍失败，按下面三步查自建后端。

1. 核对订阅转换器的 Tunnel

Cloudflare → 网络 → 隧道 → 当前隧道 → 路由 → ethan.aspool.ccwu.cc

Service URL http://192.168.0.1:25500。同一局域网访问 http://192.168.0.1:25500/version 应看到版本。失败就先看 LuCI → Docker → 容器 → SubExtended 的运行状态和端口。

版本正常，但要确认能生成 YAML

在局域网打开下方探针。应返回包含虚构节点 Probe 的 YAML。

http://192.168.0.1:25500/sub?target=clash&url=ss%3A%2F%2FYWVzLTEyOC1nY206ZGVtbw%3D%3D%40example.com%3A443%23Probe

2. WAF 管令牌，重定向只管首页

复制 WAF 表达式和首页 302 规则

Cloudflare → 网站 aspool.ccwu.cc → 安全性 → 安全规则 / WAF → 自定义规则 → defend → 编辑表达式

将占位符换成现有的后端令牌。旧规则里可从 token= 后面取值，保留令牌本身。动作选 阻止 (Block)，部署。

(http.host eq "ethan.aspool.ccwu.cc" and (
  not (http.request.uri.path in {"/sub" "/version" "/inspect"})
  or http.request.uri.args["token"][0] ne "PASTE_BACKEND_TOKEN_HERE"
))

Cloudflare → 网站 aspool.ccwu.cc → 规则 → 概述 → 单一重定向 → 编辑现有规则

(http.host eq "ethan.aspool.ccwu.cc" and http.request.uri.path eq "/")

选择「自定义筛选表达式」。目标类型选静态，填受你控制的 HTTPS 首页，例如 https://ebr.yitech.dpdns.org/。状态 302，关闭「保留查询字符串」，再部署。

订阅转换域名 ethan.aspool.ccwu.cc 沿用独立的 Access 应用。它使用现有的 Bypass → Everyone 和上面的 WAF 令牌保护。不要把它加入远程 LuCI/Zashboard 的登录应用。

3. 核对 Worker 的两个值

Cloudflare → Workers 和 Pages → 对应 Worker → 设置 → 变量和机密 → 添加 / 编辑 → 部署

  • 普通文本 default_backend 值为 https://ethan.aspool.ccwu.cc/sub。
  • 机密 SUBCONVERTER_TOKEN 值为 WAF 表达式引号里的真实令牌。只填值，不加引号、token= 或其他前缀。

这个机密非空时选 default_backend，未设置时选 custom_backend（ASUB 公共后端示例 https://url.v1.mk/sub）。前端固化或临时填写的自定义后端会优先使用，并且不带这个机密。SUB_TOKEN 负责客户端订阅链接，Tunnel 运行令牌负责连接器，三者各有用途。

验收、定位 502 和回退
  1. 公网转换域名 /version 无令牌应为 403。用 https://ethan.aspool.ccwu.cc/version?token=PASTE_BACKEND_TOKEN_HERE，替换占位符后应为 200。/sub 不应跳转到网页。真实令牌只在自己的面板或本地测试使用。
  2. 清空临时输入，重新一键复制并导入 ClashMi。主订阅应返回 YAML，包含节点或 proxy-providers。再查看 Provider 是否拉到节点。只有个别来源 403 时，先核对该来源。
  3. Worker → 可观测性 → 日志。converter_http 查上游状态、WAF 和 Tunnel；converter_invalid_profile 查是否返回了 HTML，或部署是否含 Provider 修复。ASUB · AllSub · EthanSub
  4. Worker → 部署 → 上个确认正常的版本 → ⋯ → 回滚。再次核对生效的变量。Tunnel、WAF、重定向需在各自页面恢复，KV 数据不会随 Worker 版本回滚。
