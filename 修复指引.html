A　Cloudflare Tunnel 路由修复

  • 路由器入口　https://h.aspool.ccwu.cc/
  • Zashboard 直达　https://dash.aspool.ccwu.cc/ui/zashboard/

1. 先在家里的网络打开两个面板

LuCI 用 http://192.168.0.1/。Zashboard 用下方完整路径。若局域网也打不开，进 LuCI → 服务 → OpenClash → 运行状态，先确认核心运行、面板端口是 9090。

http://192.168.0.1:9090/ui/zashboard/

2. 核对现有 Tunnel 的回源地址

Cloudflare → 网络 → 隧道 → R4S → 路由 → 编辑已发布应用程序

新建管理路由前，先完成 B 区的 Access 保护。本次修复复用了同一个 R4S 隧道。

  • h.aspool.ccwu.cc → Service URL http://192.168.0.1:80
  • dash.aspool.ccwu.cc → Service URL http://192.168.0.1:9090。这是本次修复后的 Zashboard 回源地址。
  • ethan.aspool.ccwu.cc → Service URL http://192.168.0.1:25500。转换器单独按 D 区验收。

LuCI 和 Zashboard 的 Tunnel 路径栏都留空。类型和地址分开填时，选 HTTP，地址填 192.168.0.1:端口。容器里的 127.0.0.1 指向容器自身。域名异常时，在站点 → DNS → 记录核对相应的代理 CNAME。

3. 核对 OpenClash 按钮

LuCI → 服务 → OpenClash → 插件设置 → 管理页面设置（Dashboard Settings）

公网域名填 dash.aspool.ccwu.cc，映射端口填 443，启用「管理页面公网 SSL 访问」。字段已正确就直接测试。公网浏览器使用 HTTPS，Tunnel 内侧使用上一步的 HTTP。

用手机移动数据打开公网 LuCI，登录后进入 服务 → OpenClash → 运行状态 → Zashboard。本次复测从按钮成功进入 dash.aspool.ccwu.cc/ui/zashboard/#/proxies。

面板能打开，但看不到节点或连接

先用上方 Zashboard 直达链接。面板的后端地址应为 https://dash.aspool.ccwu.cc，端口 443，使用 OpenClash 现有的管理页面登录密钥。若仍连旧的 LAN 地址，在 Zashboard 添加或切换到公网后端。页面加载但实时连接失败时，核对 Access 已覆盖整个 dash 主机名，并在 Cloudflare → 站点 → 网络核对 WebSockets。

若在登录页出现前看到 ERR_CONNECTION_CLOSED，先换网络复测，再核对 C 区的隧道状态。若是 Tunnel 502，检查对应的 Service URL 和 LAN 端口。恢复时只回退刚改的路由字段。

B　Cloudflare Access 与 Passkey 跳转

Cloudflare → Zero Trust → 访问控制 → 应用程序 → h → 编辑

  1. 「公共主机名」依次填 h.aspool.ccwu.cc 和 dash.aspool.ccwu.cc，两行路径都留空。同一自托管应用使用原来的 Allow → Include → Emails 白名单，覆盖面板、API 和 WebSocket。
  2. 「其他设置 → App Launcher 自定义」用默认的第一个域名 h.aspool.ccwu.cc。
  3. 「其他设置 → Cookie 设置」关闭「即时重定向 Cookie」（Eager redirect cookie），保存。这样从 h 登录时，Access 会等你实际访问 dash 再签发它的 Cookie。若这项改动导致管理入口回归，可把同一个开关恢复。
首次登记 Passkey 或改用已有 Passkey
  1. Zero Trust → 集成 → 标识提供程序 → 添加标识提供程序 → Passkeys → 保存。已有则跳过。
  2. 回到「应用程序 → h → 编辑 → 登录方法」，选择 Passkeys 和 One-time PIN，保存。邮件验证码作为备用。
  3. 用无痕标签直接打开公网 LuCI。首次使用选「使用 Passkey 登录 → 设置」。已登记则直接验证设备上的 Passkey。通过 Access 后再用原来的路由器账号登录，随后从 OpenClash 点 Zashboard。

若 dash 单独打不开，先用 A 区直达地址区分连接关闭、Access 登录提示、Tunnel 502 和面板后端错误。

C　R3S 的 Docker 连接器升级

这里升级的是运行在 R3S 上的 cloudflared。沿用 Cloudflare 中的 R4S 隧道、令牌和发布路由。上次验收版本为 2026.10.7。

1. 先保存配置，检查空间

LuCI → Docker → 概览 / 容器 → cloudflared → 复制/编辑

记下旧容器配置，保留重建表单。容器名用 cloudflared，网络用 bridge，重启策略用 Always。确认 Cloudflare 的「R4S → 概述」是否有另一条在线连接器。只有一条时，先准备局域网维护窗口。

LuCI → Docker → 镜像 → 拉取镜像

镜像填 cloudflare/cloudflared:latest。先拉取并确认解包完成，切换时再停止并移除旧 Docker cloudflared，腾出同名容器的位置。若报 no space left on device，上次是在原生连接器仍在线时，先移除旧容器及其旧镜像再拉取。清理前应备好配置和令牌，只选择目标容器与它的旧镜像。

2. 复制本机实际生效的运行命令

在「创建 Docker 容器 → 运行命令」粘贴下方内容。把占位符换成现有 R4S 的 Tunnel 运行令牌，提交并启动。令牌从现有容器的私有配置或该隧道的安装命令取用。

tunnel --no-autoupdate run --protocol http2 --dns-resolver-addrs 223.5.5.5:5353 --token PASTE_TUNNEL_TOKEN_HERE

本次 auto 持续尝试 QUIC，日志显示 UDP 7844 失败、TCP 7844 成功。改成 http2 后已注册两条连接。自定义 DNS 223.5.5.5:5353 沿用旧配置。这是这台 R3S 的已验收参数。其他环境可先用 auto，再按 UDP/TCP 检测结果调整。

终端里的拉取和查日志命令

在 R3S 终端使用。先拉取镜像，创建并启动容器后再查日志。

docker pull cloudflare/cloudflared:latest

docker logs --tail 80 cloudflared

3. 验证新版独立接管

  1. 在容器「日志」中找 Version、Registered tunnel connection 和 protocol=http2。Cloudflare → 网络 → 隧道 → R4S → 概述应显示新版在线、状态 Healthy，当前 5 条路由仍在。
  2. 用 A 区验证公网 LuCI 和 Zashboard，再用 D 区验证转换器。上次已确认新版独立接管后，才在 LuCI → 系统 → 启动项停止并禁用旧原生 cloudflared 的自启。面板只剩新版连接器。
  3. 若新版无法上线，查看容器日志里的 DNS 和 7844 预检结果。需要临时恢复时，在 LuCI → 系统 → 启动项启动仍安装的原生服务，再核对隧道状态。

D　订阅 502 / HTML

先重新点一次「一键复制订阅」。清空临时输入后，在 ClashMi 新增配置导入。旧订阅凭据失效可能返回伪装 HTML。若新链接仍失败，按下面三步查自建后端。

1. 核对订阅转换器的 Tunnel

Cloudflare → 网络 → 隧道 → 当前隧道 → 路由 → ethan.aspool.ccwu.cc

Service URL 用 A 区的转换器回源地址。同一局域网可访问 http://192.168.0.1:25500/version 测试端口。用下方探针确认能生成 YAML。失败时先看 LuCI → Docker → 容器 → SubExtended 的运行状态和端口。

用虚构节点验证 YAML 转换

在局域网打开下方探针。应返回包含虚构节点 Probe 的 YAML。

http://192.168.0.1:25500/sub?target=clash&url=ss%3A%2F%2FYWVzLTEyOC1nY206ZGVtbw%3D%3D%40example.com%3A443%23Probe

2. WAF 管令牌，重定向只管首页

复制 WAF 表达式和首页 302 规则

Cloudflare → 网站 aspool.ccwu.cc → 安全性 → 安全规则 / WAF → 自定义规则 → defend → 编辑表达式

将占位符换成现有的后端令牌。旧规则里可从 token= 后面取值，保留令牌本身。动作选 阻止 (Block)，部署。

(http.host eq "ethan.aspool.ccwu.cc" and (
  not (http.request.uri.path in {"/sub" "/version" "/inspect"})
  or http.request.uri.args["token"][0] ne "PASTE_BACKEND_TOKEN_HERE"
))

Cloudflare → 网站 aspool.ccwu.cc → 规则 → 概述 → 单一重定向 → 编辑现有规则

(http.host eq "ethan.aspool.ccwu.cc" and http.request.uri.path eq "/")

选择「自定义筛选表达式」。目标类型选静态，填受你控制的 HTTPS 首页，例如 https://ebr.yitech.dpdns.org/。状态 302，关闭「保留查询字符串」，再部署。

订阅转换域名 ethan.aspool.ccwu.cc 沿用独立的 Access 应用。它使用现有的 Bypass → Everyone 和上面的 WAF 令牌保护。不要把它加入远程 LuCI/Zashboard 的登录应用。

3. 核对 Worker 的两个值

Cloudflare → Workers 和 Pages → 对应 Worker → 设置 → 变量和机密 → 添加 / 编辑 → 部署

  • 普通文本 default_backend 值为 https://ethan.aspool.ccwu.cc/sub。
  • 机密 SUBCONVERTER_TOKEN 值为 WAF 表达式引号里的真实令牌。只填值，不加引号、token= 或其他前缀。

这个机密非空时选 default_backend，未设置时选 custom_backend（ASUB 公共后端示例 https://url.v1.mk/sub）。前端固化或临时填写的自定义后端会优先使用，并且不带这个机密。SUB_TOKEN 负责客户端订阅链接，Tunnel 运行令牌负责连接器，三者各有用途。

验收、定位 502 和回退
  1. 公网转换域名 /version 无令牌应为 403。用 https://ethan.aspool.ccwu.cc/version?token=PASTE_BACKEND_TOKEN_HERE，替换占位符后应为 200。/sub 不应跳转到网页。真实令牌只在自己的面板或本地测试使用。
  2. 清空临时输入，重新一键复制并导入 ClashMi。主订阅应返回 YAML，包含节点或 proxy-providers。再查看 Provider 是否拉到节点。只有个别来源 403 时，先核对该来源。
  3. Worker → 可观测性 → 日志。converter_http 查上游状态、WAF 和 Tunnel；converter_invalid_profile 查是否返回了 HTML，或部署是否含 Provider 修复。ASUB · AllSub · EthanSub
  4. Worker → 部署 → 上个确认正常的版本 → ⋯ → 回滚。再次核对生效的变量。Tunnel、WAF、重定向需在各自页面恢复，KV 数据不会随 Worker 版本回滚。
