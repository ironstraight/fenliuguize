先看错误，再决定改哪里

ClashMi 显示不支持 HTML，或订阅返回 HTTP 200 HTML
先清空前端临时输入，重新点「一键复制订阅」。旧链接的 SUB_TOKEN 不匹配时会返回伪装页。若是转换域名的 /sub 跳到网页或登录页，查重定向和Access。
Worker 报 502，响应头有 X-Subscription-Error
converter_http 表示转换器返回 HTTP 错误。先看上游状态和当前后端，私有后端 403 查 WAF，公开后端 502 可切回已验证的自建后端。converter_invalid_profile 表示转换响应不可用，查部署版本、HTML 和 YAML。超时先看转换器及订阅源响应。
转换域名出现 Cloudflare Tunnel 502 或 1033
502 优先查R3S 服务和 Tunnel 目标。1033 优先查是否有已连接的连接器。Tunnel 显示 Healthy 仍可能连不到本地服务。
主订阅有分组，只有某些 Provider 无节点
去 ClashMi 的 Provider 或内核日志看具体来源。源站自己返回 403 或超时时，核对该来源的订阅有效性，先保留 Worker 和 Tunnel 配置。

1. 先通 R3S，再核对 Tunnel

  1. 在同一局域网打开下方 /version。应看到转换器版本。若失败，在 R3S 的 LuCI → Docker → 容器 → SubExtended 看运行状态、日志及宿主机端口 25500。先确认局域网可达，再改 Cloudflare。
  2. 进入下方 Tunnel 路由。找主机名 ethan.aspool.ccwu.cc，编辑对应已发布应用。类型选 HTTP，如果面板把类型和 URL 分开，URL 只填 192.168.0.1:25500。单一 Service URL 字段用完整值。路径栏沿用现有路由范围，整主机名的路由留空。保存后确认列表显示正确。
  3. 在 转换域名区 → DNS → 记录 核对 CNAME 指向当前 Tunnel 的 <Tunnel-ID>.cfargotunnel.com，代理为橙云。在 SSL/TLS → 边缘证书 确认有效证书覆盖该主机名。公网后端用 HTTPS，Tunnel 到这台 R3S 转换器用 HTTP。

Cloudflare → 网络 (Networking) → 隧道 (Tunnels) → 选中隧道 → 路由 / 已发布应用程序路由 → 该主机名右侧 ⋯ → 编辑路由
旧版入口：Zero Trust → 网络 → 连接器 → Cloudflare Tunnels

2. 设置 WAF 和首页跳转

WAF：只放行指定路径和正确的后端令牌

Cloudflare → 网站 aspool.ccwu.cc → 安全性 → 安全规则 / WAF → 自定义规则 → 编辑 defend → 编辑表达式

  1. 在现有规则里找到 http.request.uri.args["token"][0] 右侧引号中的真实值。若仍是旧式查询字符串规则，沿用其中原来的后端令牌值，去掉 token= 前缀。将它存到自己的密码管理器，后面 Worker 也用这一值。若令牌丢失或已泄露，维护时生成新的长随机十六进制串，并同步更新所有使用该后端的 Worker。
  2. 复制表达式，把 PASTE_BACKEND_TOKEN_HERE 替换成真实值，保留表达式的引号。其他转换域名要同时替换 http.host。动作选 阻止 (Block)，部署并确认已启用。此规则比较第一个 token 的完整值，缺失也会命中阻止。
(http.host eq "ethan.aspool.ccwu.cc" and (
  not (http.request.uri.path in {"/sub" "/version" "/inspect"})
  or http.request.uri.args["token"][0] ne "PASTE_BACKEND_TOKEN_HERE"
))

若正确令牌仍被挑战或阻止，到同一站点的 安全性 → 分析 / 事件 按转换主机名、路径和时间查看具体命中的规则。应精确调整冲突规则的作用范围。

重定向：只匹配转换域名的首页

Cloudflare → 网站 aspool.ccwu.cc → 规则 → 概述 → 单一重定向 / Redirect Rule → 编辑现有规则

  1. 匹配方式选 自定义筛选表达式，粘贴下方表达式。/sub、/version、/inspect 不应命中跳转。
  2. 目标类型选 静态，填一个受你控制的 HTTPS 首页。可保留安全的既有目标，也可用下面的 ASUB 入口示例。状态码选 302，关闭「保留查询字符串」，然后部署。
(http.host eq "ethan.aspool.ccwu.cc" and http.request.uri.path eq "/")

静态目标示例 https://ebr.yitech.dpdns.org/

单一重定向先于自定义 WAF 运行。若还有旧规则把整个转换域名转走，收窄到首页。测试首页跳转时只用假参数，确认响应的 Location 没有附带原查询。

3. 检查 Zero Trust 应用和策略

Cloudflare → Zero Trust → Access controls（访问控制）→ Applications（应用程序）→ 找到转换域名对应应用 → 编辑 → Policies（策略）→ 编辑规则

ASUB 这套现有配置为 自托管应用，公开主机名是 ethan.aspool.ccwu.cc，策略动作 Bypass，规则 Include → Everyone。确认范围只覆盖该转换应用，且上一步 WAF 已启用。这样 Worker 的机器请求不会被送到 Access 登录页，由 WAF 校验令牌。

Bypass 会取消匹配请求的 Access 验证和 Access 日志。只对这套已用 WAF 防护的独立转换域名核对该配置。若策略由多个应用共用，从当前应用单独处理。其他后端若原本使用 Service Auth，核对对应代码是否发送服务令牌请求头。本项目的 SUBCONVERTER_TOKEN 只通过查询参数发送。

4. 把 WAF 的值填到 Worker

Cloudflare → Workers 和 Pages → 选对应 Worker（asub / allsub / ethansub）→ 设置 → 变量和机密 → 添加 / 编辑

  1. 检查 default_backend。用 ASUB 已验证的自建后端时，填下面完整 HTTPS URL，保留 /sub。类型为普通文本，URL 末尾不附带 ?token=。
  2. 新增或编辑类型为 机密 (Secret) 的 SUBCONVERTER_TOKEN。值填 WAF 表达式引号里面的真实值，去掉引号、空格和 token= 前缀。点 部署 (Deploy)。
  3. 打开「部署」，核对新版本已接管流量。SUB_TOKEN 仍是客户端订阅链接的凭据。Tunnel 的运行令牌、Cloudflare API Token、Access Service Token 都有各自的用途。

变量名称 default_backend SUBCONVERTER_TOKEN

自建后端值 https://ethan.aspool.ccwu.cc/sub

后端选择顺序　SUBCONVERTER_TOKEN 非空时用 default_backend，没有时用 custom_backend。若前端已固化自定义后端，或这次复制用了临时自定义后端，该覆盖优先且不带此机密。排查时先核对前端是否有覆盖，测试用清空临时输入后复制的链接。已有有效机密无需重填，面板也无法读回机密明文。

ASUB 公共后端示例（custom_backend） https://url.v1.mk/sub

5. 按顺序验收，出问题就退回上一项

  1. 边缘规则。从公网访问转换域名的 /version，无令牌或错误令牌应返回 403。正确令牌的 /version?token=真实值 应返回 200 和版本信息。首页带假参数应返回 302，Location 只包含静态目标。可在浏览器开发者工具「网络」查看原始响应，勾选「保留日志」后再访问。
  2. Worker 和客户端。打开当前项目管理页，清空临时订阅、RENAME 和自定义输入，点「一键复制订阅」，用 ClashMi 新增配置导入。主订阅应返回 200 YAML，看到节点或 proxy-providers，策略组和规则应在。再确认 Provider 有节点，点一次更新验证。200 也可能来自缓存，必要时在响应头看 X-EthanSub-Cache，以新转换和 Provider 拉取结果为准。
  3. 定位 502。在 Workers 和 Pages → 该 Worker → 可观测性 (Observability) → 日志 按出错时刻和状态筛选。对照转换域名安全事件、Tunnel 日志及 R3S Docker 日志。分享时只记状态码、错误类型和时间，遮住完整 URL 查询。

仍然失败：查版本、回退或维护连接器
  • Provider 兼容版本。在「Worker → 部署」核对含以下修复提交或其后续版本，并确认活跃流量。旧版本只认内联 proxies，或会拒绝被转换器多解码一次的签名 Provider URL。ASUB · AllSub · EthanSub
  • Worker 回退。Cloudflare → Workers 和 Pages → 对应 Worker → 部署 → 上一个已验证正常的版本右侧 ⋯ → 回滚 (Rollback)。回退后重新检查活跃版本和生效的变量，再验证订阅。Tunnel、WAF、重定向和 KV 数据需分别核对，Worker 回退不会撤销它们。若回退到只支持内联节点的版本，自建转换器的 Provider YAML 可能仍无法使用。
  • 连接器维护。Cloudflare → 网络 → 隧道 → 当前隧道 → 概述，先看每个副本是否已连接、版本是否受支持。运行令牌泄露时，在维护窗口用「刷新令牌」取得新值，逐个更新 Docker 和原生副本，确认一个重连并能转换后再处理下一个。检查同 Tunnel 的其他路由，保留至少一个已连接副本。Docker 与系统软件包按各自安装方式更新。轮换令牌 · 更新 cloudflared
